== NetApp ONTAP

The NetApp ONTAP software is the operating system that runs on AFF, ASA, and FAS storage systems. ONTAP provides a highly scalable storage architecture that enables non-disruptive operations, non-disruptive upgrades, and an agile data infrastructure. With the ONTAP One licensing model, all enterprise data services are included in a single package, simplifying deployment and management while providing full access to advanced capabilities. ONTAP delivers robust data protection through technologies such as SnapMirror for replication and disaster recovery, as well as SnapCenter for application-consistent backup and restore. It also incorporates built-in security features, including Autonomous Ransomware Protection and encryption, to safeguard data against modern threats. In addition, ONTAP enables seamless hybrid cloud integration with capabilities such as SnapMirror Cloud and S3-based replication, allowing data mobility across on-premises and cloud environments while maintaining consistency and control.

or more information about ONTAP, see the https://docs.netapp.com/us-en/ontap-family/[ONTAP Product Documentation^].

==== Multipathing and Logical Interfaces

The FlexPod architecture is designed to provide high availability if a component or a link fails in your entire compute, network, and storage stack. Multiple network paths for client access and storage access provide load balancing and optimal resource utilization. 

Multipath I/O  in ONTAP is achieved using Logical Interfaces. A LIF (logical interface) is an IP address or WWPN with associated characteristics, such as a role, a home port, a home node, a list of ports to fail over to, and a firewall policy.

==== ONTAP Snapshot, SnapMirror and SnapCenter

A snapshot is a read-only, point-in-time image of a volume. After a snapshot is created, the active file system and the snapshot point to the same disk blocks; therefore, the snapshot does not use extra disk space. Over time, the image consumes minimal storage space and incurs negligible performance overhead because it records only changes to files since the last snapshot was made. You can use a snapshot to recover individual files or LUNs, or to restore the entire contents of a volume. ONTAP compares pointer information in the snapshot with data on disk to reconstruct the missing or damaged object, without downtime or a significant performance cost.

SnapMirror is disaster recovery technology, designed for failover from primary storage to secondary storage at a geographically remote site. As its name implies, SnapMirror creates a replica, or mirror, of your working data in secondary storage from which you can continue to serve data in the event of a catastrophe at the primary site.

SnapCenter Software is a simple, centralized, scalable platform that provides application-consistent data protection for applications, databases, host file systems, and VMs running on ONTAP systems anywhere in the Hybrid Cloud.

We recommend the customers incorporate data protection in their FlexPod architecture making use of technologies such as SnapMirror for replication and disaster recovery, as well as SnapCenter for application-consistent backup and restore.

==== Secure Multi-Tenancy

Secure multi-tenancy is the use of secure virtual partitions within a shared physical storage environment for the purpose of sharing the physical environment among multiple distinct tenants. For instance, a storage service provider might configure a storage array in such a way that each of three different customers is provisioned a certain portion of the array’s disk capacity and network resources. In a secure multi-tenant environment, each customer would have access only to the resources explicitly provisioned to that customer. The customer would not have access to other customers’ data or even be aware of the existence of the other customers or the fact that they share a common physical array. Secure multi-tenant environments should also provide a means to make sure that no single tenant consumes so much of the shared performance capability so as to affect the other tenants.

Multi-tenancy in ONTAP is achieved via storage virtual machines(SVMs) and IP Spaces. 

Like a virtual machine running on a hypervisor, an SVM is a logical entity that abstracts physical resources. An SVM serves data to clients and hosts from one or more volumes, through one or more network logical interfaces (LIFs). 

IPspaces enable you to configure a single ONTAP cluster so that it can be accessed by clients from more than one administratively separate network domain, even if those clients are using the same IP address subnet range. This allows for separation of client traffic for privacy and security.
